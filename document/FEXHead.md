# FEX Head

## Overview

- **Purpose**: Parallel mapping of pre-trained MODSR/expression source-side embeddings (token-wise embeddings) to fixed-length FEX token sequences (for fixed-depth binary tree encoding and subsequent parsing).
- **Location**: Implementation is in `FEXHeadModel` in `train_fex_head_2.py` (same file contains dataset and evaluation logic); FEX encoder implementation is in `symbolicregression/envs/fixed_tree_encoder.py`.
- **Input**: A batch of source embedding tensors `src_embeds`, shape `(B, S, Src_Dim)`, typically from frozen MODSR generator/embedding layer.
- **Output**: Corresponding logits, shape `(B, T, Vocab)`, where T is target FEX sequence length (including BOS/EOS), Vocab is FEX vocabulary size.

## Design Highlights

- Non-autoregressive (parallel) decoding: Uses a set of learnable fixed queries (`query_embed`) as queries for each target position, enabling the model to predict the entire FEX sequence in parallel, suitable for fixed-length, tree-structured encoding.
- Source-side first adds position encoding (`src_pos_embed`), then projects to `d_model` via linear layer `src_proj` as memory for Transformer Decoder.
- Uses standard `nn.TransformerDecoder` (or NPU-compatible layer) for multi-layer interaction, output mapped to vocabulary logits via `output_head`.
- Training dataset is `FEXOnTheFlyDataset`, responsible for sampling from raw expressions, generating FEX tokens with `FixedTreeEncoder`, and returning `(src_tokens, tgt_tokens)` pairs.

## Integration and Execution

- Test/inference call examples (quick reference) are in [infer_modsr_fex.py](infer_modsr_fex.py); common command-line parameters: `--fex_head_checkpoint` specifies head model weights, `--e2e_checkpoint`/`--snip_checkpoint` for loading source-side embedding weights (to construct `src_embedding_layer`).
- Evaluation mode function `evaluate_tokens` (in `train_fex_head_2.py`) demonstrates the complete workflow: load MODSR checkpoint to extract embedding weights -> construct `FEXHeadModel` -> load `fex_head_checkpoint` -> output FEX tokens/expressions for source token sequences.

## Training Notes

- Target FEX sequences generated by `FEXOnTheFlyDataset` are of fixed length (controlled by `depth`, e.g., depth=6 -> length upper bound), ensure `max_len` covers the maximum possible length during training.
- Source-side embeddings should align with vocabulary/embedding_dim used during training; the script includes compatibility handling for vocab-size mismatch when loading checkpoint (can extend embedding and remove `padding_idx`).
- Encoding failures (some randomly generated trees may not be encodable by FEX) are skipped and resampled, dataset contains failure count logging for quality monitoring.
